---
title: perform
description: Update stores and call events or effects in one synchronous action
---

`perform` groups the logic of one action in a single function. Use it when a task
would otherwise require several `sample` calls with branching and intermediate events.

Inside `action`, use ordinary `if` statements and call the callbacks provided by
`target`. These calls collect values; Effector propagates them after `action`
finishes. Dependencies remain declared in `source`, `clock`, and `target`.

:::info{title="since"}
[effector 23.5.0](https://changelog.effector.dev/#effector-23-5-0)
:::

## Usage

### Writing to a store

Pass a store to `target`. The first argument of `action` is a callback that accepts
its new value. Without `clock`, `perform` returns an event that runs the action:

```ts
import {createEffect, createEvent, createStore, perform} from 'effector'

const $count = createStore(0)
const setCount = perform({
  target: $count,
  action: (set, amount: number) => {
    set(amount)
  },
})

setCount(2)
```

The event payload is passed to `action` after the target callbacks. Its type is
inferred from the parameter annotation.

### Reading state and choosing targets

Pass stores to `source` to read their values in `action`. These values become the
second argument, before the event payload. For an object of stores, a leading `$`
is removed from its keys: `source: {$name}` gives `{name}`.

Use an object in `target` to update several units. Its keys become callbacks:

```ts
const $name = createStore('')
const $error = createStore('')
const saveNameFx = createEffect(async (name: string) => {
  await fetch('/api/name', {method: 'POST', body: name})
})

const submit = perform({
  source: {$name},
  target: {error: $error, saveNameFx},
  action: (target, {name}) => {
    const trimmed = name.trim()
    if (!trimmed) {
      target.error('Enter a name')
      return
    }
    target.error('')
    target.saveNameFx(trimmed)
  },
})

submit()
```

Only called targets are triggered. Here an empty name updates the error without
starting the effect. Target callbacks return nothing, including effect callbacks.

### Reading and updating the same store

To read and update a store, pass it to both `source` and `target`.
`action` receives a setter as its first argument and the current store value as
its second. Calculate the new value and pass it to the setter:

```ts
const increment = perform({
  source: $count,
  target: $count,
  action: (setCount, count, amount: number) => {
    setCount(count + amount)
  },
})

increment(2)
```

### Resetting a store

Store callbacks expose `.reinit()`:

```ts
const reset = perform({
  target: {count: $count},
  action: target => {
    target.count.reinit()
  },
})
```

### External clock

Pass `clock` to run the action on an existing unit or array of units:

```ts
const amountChanged = createEvent<number>()

perform({
  clock: amountChanged,
  target: $count,
  action: (setCount, amount) => {
    setCount(amount)
  },
})
```

With `clock`, `perform` returns nothing. The clock payload is the last argument of
`action`.

## Configuration

- **`target`** — a writable store, callable event, effect, or object of these units.
  Required. The first `action` argument mirrors this shape, replacing units with callbacks.
- **`source`** — a store or object of stores. Its values are passed as the second
  argument of `action`. A leading `$` is removed from object keys:
  `source: {$name}` gives `{name}`. Target keys remain unchanged.
- **`clock`** — a unit or array of units that triggers the action. If omitted,
  a new callable event is returned.
- **`action`** — a required synchronous, pure function:
  `(target, payload) => void`, or `(target, source, payload) => void` with `source`.
  Route side effects through `target`, not direct calls to units.
- **`batch`** — `true` by default; controls batching as in [`sample`](/en/api/effector/sample).
- **`name`, `sid`** — optional metadata for the returned event.

## Restrictions

- Call each target at most once per action. Repeated calls log a warning and only
  the last payload is used, including calls through different keys for the same unit.
- Do not use `async` or save target callbacks for later. A call after `action`
  finishes throws. Start asynchronous work through an effect in `target`.
- If `action` throws, none of its collected target calls are applied.

## Coming from effector-action

`perform` follows the synchronous [`createAction`](https://github.com/AlexeyDuybo/effector-action)
model. It uses `action` instead of `fn` and accepts one configuration object.
Reducer setters, callback return values, a separate clock argument, and
`createAsyncAction` are not supported.
