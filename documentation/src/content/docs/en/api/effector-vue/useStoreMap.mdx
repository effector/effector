```ts
import { useStoreMap } from "effector-vue/composition";
```

Function, which subscribes to a [store](/en/api/effector/Store) and transforms its value with a given selector. The returned `ComputedRef` updates only when the result of the selector changes, so a component reading one item of a large store is not touched by the updates of the other items.

# Methods (#methods)

## `useStoreMap($store, fn)` (#methods-useStoreMap-store-fn)

### Formulae (#methods-useStoreMap-store-fn-formulae)

```ts
useStoreMap(
  $store: Store<State>,
  fn: (state: State) => Result,
  opts?: {scope?: Scope, forceScope?: boolean},
): ComputedRef<Result>;
```

### Arguments (#methods-useStoreMap-store-fn-arguments)

1. `$store`: Source [`Store<State>`](/en/api/effector/Store)
2. `fn` (_(state) => result_): Selector function to receive part of source store
3. `opts` (_Object_): Optional [scope](/en/api/effector-vue/EffectorScopePlugin) options

### Returns (#methods-useStoreMap-store-fn-returns)

(`ComputedRef<Result>`)

## `useStoreMap(config)` (#methods-useStoreMap-config)

### Formulae (#methods-useStoreMap-config-formulae)

```ts
useStoreMap({
  store: Store<State>,
  keys?: MaybeRefOrGetter<Keys>,
  fn: (state: State, keys: Keys) => Result,
  updateFilter?: (update: Result, current: Result) => boolean,
  defaultValue?: Result,
  scope?: Scope,
  forceScope?: boolean,
}): ComputedRef<Result>;
```

### Arguments (#methods-useStoreMap-config-arguments)

1. `params` (_Object_): Configuration object
   - `store`: Source [store](/en/api/effector/Store)
   - `keys` (`MaybeRefOrGetter<Keys>`): Passed to `fn` as its second argument. A getter or a ref is tracked, so the selector runs again when it changes. A plain value is used as it is
   - `fn` (`(state: State, keys: Keys) => Result`): Selector function to receive part of source store
   - `updateFilter` (`(update: Result, current: Result) => boolean`): Decides whether a new result of `fn` replaces the current one. Defaults to `update !== current`
   - `defaultValue` (`Result`): Used every time `fn` returns `undefined`
   - `scope` ([`Scope`](/en/api/effector/Scope)) and `forceScope` (`boolean`): [Scope](/en/api/effector-vue/EffectorScopePlugin) options of the call

### Returns (#methods-useStoreMap-config-returns)

(`ComputedRef<Result>`)

### Examples (#methods-useStoreMap-config-examples)

This hook is very useful for working with lists, especially with large ones

##### User.vue (#methods-useStoreMap-config-example-userVue)

```vue
<script setup>
import { useStoreMap } from "effector-vue/composition";

import { $users } from "./model";

const props = defineProps({
  id: Number,
});

const user = useStoreMap({
  store: $users,
  keys: () => props.id,
  fn: (users, userId) => users.find(({ id }) => id === userId),
  defaultValue: { name: "unknown" },
});
</script>

<template>
  <div>
    <strong>[{{ id }}]</strong> {{ user.name }}
  </div>
</template>
```

##### App.vue (#methods-useStoreMap-config-examples-appVue)

```vue
<script setup>
import { useUnit } from "effector-vue/composition";

import { $ids } from "./model";
import User from "./User.vue";

const ids = useUnit($ids);
</script>

<template>
  <div>
    <User v-for="id in ids" :key="id" :id="id" />
  </div>
</template>
```

##### model.ts (#methods-useStoreMap-config-examples-model)

```ts
import { createStore } from "effector";

export const $users = createStore([
  { id: 1, name: "Yung" },
  { id: 2, name: "Lean" },
  { id: 3, name: "Kyoto" },
  { id: 4, name: "Sesh" },
]);

export const $ids = createStore([1, 2, 3, 4]);

export const $count = createStore(0);
```

### Filtering updates (#methods-useStoreMap-config-updateFilter)

`updateFilter` receives the results of `fn`, not the state of the store. A rejected result is dropped, and the previous one stays until an accepted one arrives. A recompute caused by `keys` goes through the filter as well.

```js
const evenCount = useStoreMap({
  store: $count,
  fn: (count) => count,
  updateFilter: (update) => update % 2 === 0,
});
```

During a server render there is nothing to filter: the value follows the store until the render ends, and `updateFilter` is not called.
