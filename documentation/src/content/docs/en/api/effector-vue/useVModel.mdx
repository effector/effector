```ts
import { useVModel } from "effector-vue/composition";
```

A hook function, which subscribes to a watcher that observes changes in the current store, so when recording results, the component will automatically update. It is primarily used when working with forms (`v-model`) in Vue 3.

# Methods (#methods)

## `useVModel($store, options?)` (#methods-useVModel-store)

### Formulae (#methods-useVModel-store-formulae)

```ts
useVModel($store: Store<State>, options?: UseVModelOptions): Ref<UnwrapRef<State>>;
useVModel<T extends Record<string, Store<any>>>(shape: T, options?: UseVModelOptions): ExtractStore<T>;
```

Designed for Vue 3.

### Arguments (#methods-useVModel-store-arguments)

1. `$store` ([_Store_](/en/api/effector/Store)) or a shape of stores
2. `options?` (_Object_)
   - `scope?` ([_Scope_](/en/api/effector/Scope)) to read and to write instead of the scope of the plugin
   - `forceScope?` (_boolean_) throw when no scope is resolved instead of falling back to global mode
   - `deep?` (_boolean_) watch the value deeply, so that an edit of a nested field reaches the store (default: `true`)

### Returns (#methods-useVModel-store-returns)

A writable `Ref` with a copy of the state, or an object of such copies for a shape of stores. Editing it writes the whole new value into the store; an update of the store replaces the copy.

### Examples (#methods-useVModel-examples)

#### Single Store (#methods-useVModel-examples-singleStore)

```js
import { createStore, createApi } from "effector";
import { useVModel } from "effector-vue/composition";

const $user = createStore({
  name: "",
  surname: "",
  skills: ["CSS", "HTML"],
});

export default {
  setup() {
    const user = useVModel($user);

    return { user };
  },
};
```

```html
<div id="app">
  <input type="text" v-model="user.name" />
  <input type="text" v-model="user.surname" />

  <div>
    <input type="checkbox" v-model="user.skills" value="HTML" />
    <input type="checkbox" v-model="user.skills" value="CSS" />
    <input type="checkbox" v-model="user.skills" value="JS" />
  </div>
</div>
```

#### Store Shape (#methods-useVModel-examples-storeShape)

```js
import { createStore, createApi } from "effector";
import { useVModel } from "effector-vue/composition";

const $name = createStore("");
const $surname = createStore("");
const $skills = createStore([]);

const model = {
  name: $name,
  surname: $surname,
  skills: $skills,
};

export default {
  setup() {
    const user = useVModel(model);

    return { user };
  },
};
```

```html
<div id="app">
  <input type="text" v-model="user.name" />
  <input type="text" v-model="user.surname" />

  <div>
    <input type="checkbox" v-model="user.skills" value="HTML" />
    <input type="checkbox" v-model="user.skills" value="CSS" />
    <input type="checkbox" v-model="user.skills" value="JS" />
  </div>
</div>
```

#### Scope (#methods-useVModel-examples-scope)

Under [`EffectorScopePlugin`](/en/api/effector-vue/EffectorScopePlugin) the form reads and writes the scope of the application, so the input of the user reaches `scope.getState($form)` and [`serialize`](/en/api/effector/serialize). Without a scope the store itself is written, as before.

```js
import { fork } from "effector";
import { EffectorScopePlugin } from "effector-vue/composition";

const scope = fork();
app.use(EffectorScopePlugin({ scope }));
```

A call outside of a component, or a call that has to write into another scope, takes the scope as an option:

```js
const form = useVModel($form, { scope });
```

#### Shallow binding (#methods-useVModel-examples-deep)

By default the copy is watched deeply, so an edit of a nested field writes the whole new value into the store. With `deep: false` the state of the store is bound as it is and only an assignment of the whole value is written back, which suits a form of primitives or a large state that is mostly read:

```js
const form = useVModel($form, { deep: false });

form.value = { ...form.value, name: "John" };
```

In this mode the ref holds the state object of the store itself, and an assignment hands that object back without a copy. Writing into a nested field of it changes the state of the store in place, and nothing reads that as an update: the store keeps the same object and no watcher fires. Replace the whole value, the way the example does, or leave `deep` alone.

### Limitations (#methods-useVModel-limitations)

- The copy of the state is made with `structuredClone`, so `Date`, `Map`, `Set`, `RegExp` and typed arrays survive the round trip. If the runtime has no `structuredClone`, or it throws on some value in the state, a function for one, the whole copy is made with a plain recursive copy instead. That copy keeps functions and dates by reference and turns `Map` and `Set` into empty objects. A class instance loses its prototype either way.
- A derived store, the result of `map` or `combine`, takes an edit, and the next update of the store it is computed from overwrites it. The composable reports it through `console.error`; bind the form to that store.
- The second argument used to be a Vue `EffectScope`. It still works; the options object is the preferred form.
