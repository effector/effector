`perform` описывает императивную логику одного синхронного действия: локальные
вычисления, ветвления и выбор сторов для обновления, событий и эффектов для запуска.
Зависимости остаются явно заданными в `source`, `clock` и `target`.

Используйте [`sample`](/ru/api/effector/sample) для прямой связи clock или source
с target, в том числе с преобразованием или фильтром. Выбирайте `perform`, когда
одну задачу понятнее выразить функцией с ранними выходами и несколькими выбранными
вызовами targets, а не цепочкой `sample`. Для единственного присваивания обёртка
из `perform` не нужна.

:::info{title="Начиная с"}
[effector 23.5.0](https://changelog.effector.dev/#effector-23-5-0)
:::

## Проверка и отправка формы

Действие убирает пробелы по краям имени, отклоняет пустой ввод, а иначе сбрасывает
ошибку, нормализует ввод и запускает сохранение:

```ts
import {createEffect, createStore, perform} from 'effector'

const $name = createStore('')
const $error = createStore('')
const saveNameFx = createEffect(async (name: string) => {
  const response = await fetch('/api/name', {method: 'POST', body: name})
  if (!response.ok) throw new Error('Could not save name')
  return name
})

const submit = perform({
  source: {$name, saving: saveNameFx.pending},
  target: {$name, $error, saveNameFx},
  action: (target, {name, saving}) => {
    if (saving) return

    const trimmed = name.trim()
    if (!trimmed) {
      target.$error('Введите имя')
      return
    }

    target.$error.reinit()
    if (trimmed !== name) target.$name(trimmed)
    target.saveNameFx(trimmed)
  },
})

submit()
```

- **`source` — чтение состояния.** Его значения передаются вторым аргументом
  `action`. Начальный `$` удаляется из ключей объекта: `{$name}` становится `{name}`.
- **`target` — запись и вызовы.** Его юниты становятся колбэками в первом аргументе.
  Ключи не меняются: `$name` становится `target.$name`.
  Колбэк стора принимает новое значение; `.reinit()` восстанавливает значение по умолчанию.
- **Чтение и запись разделены.** `$name` указан и в `source`, и в `target`, потому
  что действие читает и обновляет его. Объявление стора только в `target` не даёт
  доступа к его текущему значению.
- **Без `clock` метод `perform` возвращает вызываемое событие.** Здесь `submit()`
  запускает действие. Для события с payload укажите тип последнего параметра
  `action`, например `(target, source, payload: string) => { ... }`.

Срабатывают только вызванные targets. Вызовы собирают payload; Effector передаёт
их целевым юнитам после завершения `action`, а не на строке вызова каждого колбэка.
Значения source не меняются в ходе действия. Колбэки targets ничего не возвращают,
в том числе колбэки эффектов: `target.saveNameFx(...)` не возвращает промис.

## Реакция на внешний clock

Продолжим пример формы обработкой успешного сохранения. Сохранённое имя записываем
всегда, но очищаем форму, только если пользователь не ввёл другое имя, пока
выполнялся запрос:

```ts
const $savedName = createStore('')

perform({
  clock: saveNameFx.doneData,
  source: {$name},
  target: {$name, $error, $savedName},
  action: (target, {name}, savedName) => {
    target.$savedName(savedName)
    if (name.trim() !== savedName) return

    target.$name.reinit()
    target.$error.reinit()
  },
})
```

С `clock` метод `perform` ничего не возвращает. Payload clock передаётся последним
аргументом `action`, а его тип выводится из clock. Здесь эффект выполняется
асинхронно, но каждое действие синхронно: отправка и успешное завершение — отдельные
шаги, связанные через `saveNameFx.doneData`.

## Конфигурация

`perform` принимает один объект конфигурации:

- **`target`** — обязательный записываемый стор, вызываемое событие, эффект или
  объект таких юнитов. Первый аргумент `action` повторяет эту форму, заменяя юниты
  колбэками. Для одного юнита этот аргумент — один колбэк.
- **`source`** — стор или объект сторов для чтения. Значение или значения передаются
  вторым аргументом `action`. Начальный `$` удаляется только из ключей объекта source,
  но не target.
- **`clock`** — юнит или массив юнитов, запускающих действие. Если не указан,
  возвращается новое вызываемое событие. Задавайте `clock` внутри конфигурации,
  а не отдельным аргументом.
- **`action`** — обязательная синхронная функция:
  `(target, payload) => void` или `(target, source, payload) => void` при наличии `source`.
  Вычисления должны быть чистыми; запускайте побочные эффекты через колбэки targets,
  а не прямыми вызовами юнитов или операциями ввода-вывода.
- **`batch`** — по умолчанию `true`; управляет батчингом, как в [`sample`](/ru/api/effector/sample).
- **`name`, `sid`** — необязательные метаданные возвращаемого события.

## Ограничения

- Вызывайте каждый target не более одного раза за действие. Повторные вызовы выводят
  предупреждение; используется только последний payload. Это относится и к вызовам
  одного юнита через разные ключи.
- Не используйте `async` для action и не сохраняйте колбэки targets на потом. Вызов
  после завершения `action` выбросит ошибку. Асинхронную работу запускайте через эффект в `target`.
- Если `action` выбросит ошибку, ни один из собранных вызовов targets не будет применён.

## Переход с effector-action

`perform` следует модели синхронного [`createAction`](https://github.com/AlexeyDuybo/effector-action),
используя `action` вместо `fn`. Поле `update`, редьюсеры в колбэках сторов,
возвращаемые колбэками значения, отдельный аргумент clock и аналог `createAsyncAction`
не поддерживаются.
