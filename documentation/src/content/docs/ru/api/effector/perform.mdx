`perform` собирает логику одного действия в одной функции. Используйте его, когда
иначе пришлось бы писать несколько `sample` с ветвлениями и промежуточными событиями.

Внутри `action` можно использовать обычные `if` и вызывать колбэки из `target`.
Эти вызовы собирают значения; Effector передаёт их целевым юнитам после завершения
`action`. Зависимости остаются явно заданными в `source`, `clock` и `target`.

## Использование

### Запись в стор

Передайте стор в `target`. Первый аргумент `action` — колбэк, принимающий новое
значение стора. Без `clock` метод `perform` возвращает событие, запускающее действие:

```ts
import {createEffect, createEvent, createStore, perform} from 'effector'

const $count = createStore(0)
const setCount = perform({
  target: $count,
  action: (set, amount: number) => {
    set(amount)
  },
})

setCount(2)
```

Payload события передаётся в `action` после колбэков targets. Его тип выводится
из аннотации параметра.

### Чтение состояния и выбор targets

Передайте сторы в `source`, чтобы читать их значения в `action`. Они станут вторым
аргументом, перед payload события. У объекта сторов начальный `$` удаляется
из ключей: `source: {$name}` даёт `{name}`.

Для обновления нескольких юнитов передайте объект в `target`. Его ключи станут колбэками:

```ts
const $name = createStore('')
const $error = createStore('')
const saveNameFx = createEffect(async (name: string) => {
  await fetch('/api/name', {method: 'POST', body: name})
})

const submit = perform({
  source: {$name},
  target: {error: $error, saveNameFx},
  action: (target, {name}) => {
    const trimmed = name.trim()
    if (!trimmed) {
      target.error('Введите имя')
      return
    }
    target.error('')
    target.saveNameFx(trimmed)
  },
})

submit()
```

Срабатывают только вызванные targets. Здесь пустое имя обновляет ошибку, но не
запускает эффект. Колбэки targets ничего не возвращают, в том числе колбэки эффектов.

### Чтение и запись одного и того же стора

Чтобы прочитать и обновить стор, передайте его и в `source`, и в `target`.
Первым аргументом `action` получит функцию записи, вторым — текущее значение стора.
Вычислите новое значение и передайте его в функцию записи:

```ts
const increment = perform({
  source: $count,
  target: $count,
  action: (setCount, count, amount: number) => {
    setCount(count + amount)
  },
})

increment(2)
```

### Сброс стора

У колбэков сторов есть метод `.reinit()`:

```ts
const reset = perform({
  target: {count: $count},
  action: target => {
    target.count.reinit()
  },
})
```

### Внешний clock

Передайте `clock`, чтобы запускать действие от существующего юнита или массива юнитов:

```ts
const amountChanged = createEvent<number>()

perform({
  clock: amountChanged,
  target: $count,
  action: (setCount, amount) => {
    setCount(amount)
  },
})
```

С `clock` метод `perform` ничего не возвращает. Payload clock передаётся последним
аргументом `action`.

## Конфигурация

- **`target`** — записываемый стор, вызываемое событие, эффект или объект таких юнитов.
  Обязателен. Первый аргумент `action` повторяет эту форму, заменяя юниты колбэками.
- **`source`** — стор или объект сторов. Их значения передаются вторым аргументом
  `action`. Начальный `$` удаляется из ключей объекта:
  `source: {$name}` даёт `{name}`. Ключи target не меняются.
- **`clock`** — юнит или массив юнитов, запускающих действие. Если не указан,
  возвращается новое вызываемое событие.
- **`action`** — обязательная синхронная чистая функция:
  `(target, payload) => void` или `(target, source, payload) => void` при наличии `source`.
  Побочные эффекты запускайте через `target`, а не прямыми вызовами юнитов.
- **`batch`** — по умолчанию `true`; управляет батчингом, как в [`sample`](/ru/api/effector/sample).
- **`name`, `sid`** — необязательные метаданные возвращаемого события.

## Ограничения

- Вызывайте каждый target не более одного раза за действие. Повторные вызовы выводят
  предупреждение; используется только последний payload. Это относится и к вызовам
  одного юнита через разные ключи.
- Не используйте `async` и не сохраняйте колбэки targets на потом. Вызов после
  завершения `action` выбросит ошибку. Асинхронную работу запускайте через эффект в `target`.
- Если `action` выбросит ошибку, ни один из собранных вызовов targets не будет применён.

## Переход с effector-action

`perform` следует модели синхронного [`createAction`](https://github.com/AlexeyDuybo/effector-action).
Он использует `action` вместо `fn` и принимает один объект конфигурации.
Редьюсеры в колбэках сторов, возвращаемые колбэками значения, отдельный аргумент clock
и `createAsyncAction` не поддерживаются.
